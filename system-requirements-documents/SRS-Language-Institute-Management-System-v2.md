## ۱. مقدمه

### ۱.۱ هدف سند
این سند نسخه تکمیلی نیازمندی‌های کارکردی و غیرفعالیتی سیستم مدیریت آموزشگاه زبان است و مبنای طراحی معماری، پیاده‌سازی، آزمون پذیرش و برنامه‌ریزی فازها قرار می‌گیرد.

### ۱.۲ دامنه سیستم
پلتفرم یکپارچه شامل:
1. وب‌سایت عمومی و جذب مخاطب
2. پنل زبان‌آموز (و در صورت نیاز والدین)
3. پنل مدرس
4. پنل منشی / مالی / پشتیبانی
5. داشبورد مدیریتی چندشعبه

سیستم از آموزش **حضوری، آنلاین و ترکیبی** پشتیبانی می‌کند و چرخه کامل از جذب سرنخ تا گواهینامه و گزارش مدیریتی را پوشش می‌دهد.

### ۱.۳ خارج از دامنه (فعلاً)
- اپلیکیشن بومی موبایل (iOS/Android) — فقط آماده‌سازی API
- هوش مصنوعی تصحیح رایتینگ/اسپیکینگ پیشرفته — فاز آینده
- حسابداری کامل شرکتی (حقوق بیمه تکمیلی و دفاتر قانونی) — فقط ماژول ساده‌شده حقوق مدرس
- LMS دانشگاهی کامل با SCORM پیشرفته — پشتیبانی سبک در فازهای بعدی

### ۱.۴ ذی‌نفعان

| نقش | توضیح |
|-----|--------|
| مدیر سیستم / مالک | تنظیمات کلان، شعب، نقش‌ها، گزارش‌های استراتژیک |
| مدیر آموزشگاه / شعبه | عملیات روزانه شعبه، ظرفیت، تخفیف، کیفیت آموزش |
| منشی / پذیرش | ثبت‌نام، نوبت مشاوره، پیگیری پرداخت |
| کارشناس مالی | اقساط، بدهی، استرداد، گزارش درآمد |
| مدرس | کلاس، حضور، نمره، تکلیف، بازخورد |
| زبان‌آموز | یادگیری، آزمون، پرداخت، پیشرفت |
| والدین / سرپرست | مشاهده وضعیت فرزند (دوره‌های کودک/نوجوان) |
| بازدیدکننده / سرنخ | مشاهده محتوا و ثبت درخواست مشاوره |

### ۱.۵ تعاریف کلیدی

| اصطلاح | تعریف |
|--------|--------|
| Course | قالب آموزشی (زبان، سطح، سرفصل، شهریه پایه) |
| Class | اجرای یک دوره در بازه زمانی با مدرس، ظرفیت و شعبه |
| Session | یک جلسه مشخص از کلاس (تاریخ/ساعت/مکان یا لینک) |
| SessionType | نوع جلسه: عادی، جبرانی، آزمایشی، آزمون، کارگاه |
| Enrollment | ثبت‌نام زبان‌آموز در یک Class |
| Waitlist | صف انتظار هنگام تکمیل ظرفیت |
| Placement Test | آزمون تعیین سطح |
| Soft Delete | غیرفعال‌سازی منطقی بدون حذف فیزیکی رکورد |
| Audit Log | ثبت تغییرات حساس با کاربر، زمان و مقدار قبل/بعد |
| Lead | سرنخ فروش/مشاوره قبل از تبدیل به زبان‌آموز |

## ۲. توصیف کلی سیستم

### ۲.۱ چشم‌انداز
سامانه‌ای یکپارچه برای افزایش نرخ تبدیل مشاوره به ثبت‌نام، کاهش خطای عملیاتی، شفافیت مالی، ارتقای کیفیت آموزش و تصمیم‌گیری داده‌محور در آموزشگاه‌های تک‌شعبه و چندشعبه.

### ۲.۲ معماری منطقی

```
[React + Bootstrap SPA]
        │ HTTPS / JWT
        ▼
[FastAPI — REST + OpenAPI]
   │         │         │
   ▼         ▼         ▼
SQL Server  SMS/Email  Payment Gateway
            Storage     (و در صورت نیاز Meeting Link Provider)
```

پیشنهاد فنی نسخه ۲:
- احراز هویت: JWT + Refresh Token
- مستندسازی API با OpenAPI/Swagger
- آپلود فایل روی storage کنترل‌شده (مسیر محلی یا object storage)
- Jobهای پس‌زمینه برای یادآوری اقساط، پیامک و پشتیبان‌گیری
- Health Check برای مانیتورینگ سرویس

### ۲.۳ اصول طراحی پیشنهادی
- API-First برای آمادگی موبایل آینده
- RBAC دقیق + حداقل دسترسی لازم
- اعتبارسنجی دو لایه (Frontend + Backend)
- Idempotent بودن عملیات پرداخت
- چندزبانه بودن UI و پیام‌ها (FA/EN)
- قابلیت پیکربندی قواعد کسب‌وکار به‌جای hard-code

### ۲.۴ مفروضات
- دسترسی اینترنت پایدار برای کاربران
- درگاه پرداخت و پنل پیامک/ایمیل در دسترس است
- استاندارد سطح زبان (CEFR یا معادل داخلی) توسط آموزشگاه تأیید می‌شود
- تقویم شمسی در UI فارسی و تبدیل مناسب تاریخ در بک‌اند پشتیبانی می‌شود

### ۲.۵ محدودیت‌ها
- پشته: React + Bootstrap + FastAPI + SQL Server
- سازگاری با Chrome، Edge، Firefox، Safari (آخرین دو نسخه عمده)
- پشتیبانی RTL برای فارسی و LTR برای انگلیسی

## ۳. مدل مفهومی دامنه (اصلاح‌شده)

### ۳.۱ سلسله‌مراتب آموزشی
`Language → Level (CEFR/Custom) → Course → Class → Session`

### ۳.۲ چرخه عمر زبان‌آموز (پیشنهادی)
`Visitor → Lead → Placement → Enrollment → Active Learning → Assessment → Certificate → Retention/Upsell`

### ۳.۳ وضعیت‌های پیشنهادی

**Enrollment:** `pending_payment` | `pending_approval` | `active` | `frozen` | `completed` | `withdrawn` | `transferred`

**Payment:** `draft` | `pending` | `paid` | `failed` | `refunded` | `partially_paid` | `overdue`

**Session:** `scheduled` | `in_progress` | `completed` | `cancelled` | `rescheduled`

**Class:** `draft` | `open` | `full` | `in_progress` | `finished` | `cancelled`

## ۹. سناریوهای اصلی پذیرش (نمونه)

1. **ثبت‌نام تا پرداخت:** بازدیدکننده دوره را فیلتر می‌کند → تعیین سطح اختیاری → ثبت‌نام در Class → پرداخت آنلاین → رسید و دسترسی به منابع.
2. **ظرفیت کامل:** Class پر است → ورود به Waitlist → انصراف یک نفر → دعوت خودکار نفر اول صف → مهلت پرداخت.
3. **غیبت مدرس:** لغو Session با دلیل → تعیین جایگزین (اگر تنظیم فعال باشد) یا زمان جبرانی → اطلاع‌رسانی به فراگیران.
4. **پایان دوره:** ثبت نمرات نهایی → بررسی حد نصاب حضور → صدور گواهینامه QR → پیشنهاد دوره بعدی.
5. **اقساط معوق:** رسیدن سررسید → یادآوری پیامک/ایمیل → تغییر وضعیت مالی به معوق → محدودیت ثبت‌نام جدید تا تسویه (قابل تنظیم).
